```python
# src/services/pipeline_view/service.py — ПОСЛЕ рефакторинга

class DocumentPipelineViewService:
    """Фасад: собирает стадии пайплайна из отдельных билдеров."""

    def __init__(self, session: AsyncSession):
        self._session = session
        self._artifact_store = ArtifactStore()
        self._doc_repo = DocumentRepository(session)
        self._version_repo = DocumentVersionRepository(session)
        # билдеры стадий
        self._source = SourceStageBuilder(self._artifact_store)
        self._primary = PrimaryStageBuilder(self._artifact_store)
        self._extract = ExtractStageBuilder(self._artifact_store)
        self._pii = PiiStageBuilder(self._artifact_store)
        self._structure = StructureStageBuilder(session, self._artifact_store)
        self._chunks = ChunksStageBuilder(session, self._artifact_store)

    async def build(self, document_id: UUID) -> DocumentPipelineViewResponseDTO:
        doc = await self._doc_repo.get(document_id)
        version = await self._version_repo.get_latest(document_id)
        meta = base_meta(doc)
        return DocumentPipelineViewResponseDTO(
            stages=[
                self._source.build(doc, version, meta),
                self._primary.build(doc, version, meta),
                self._extract.build(doc, version, meta),
                self._pii.build(doc, version, meta),
                await self._structure.build(doc, version, meta),
                await self._chunks.build(doc, version, meta),
            ]
        )
```

**Трудоёмкость:** ~3-4 часа
**Риск:** Низкий — это read-only сервис, ничего не мутирует

## 📐 Общие антипаттерны, обнаруженные в проекте

### 1. Дублирование хелперов

`_normalize_uid()` встречается **3 раза** в `document_pipeline_view_service.py`
(строки 712, 1355, 1571). `_chunk_sort_key()` — **2 раза** (строки 748, 1609).

**Решение:** Вынести в `normalizers.py` один раз.

### 2. Workers содержат бизнес-логику

Файлы в `src/workers/` (chunk_builder 700, run_orchestrator 734,
extract_worker 616) содержат бизнес-логику вместе с Celery-обёрткой.

**Решение:** Worker должен быть тонким — вызывать сервис.
```python
# workers/chunk_builder.py — ПОСЛЕ
@celery_app.task
def build_chunks(doc_id):
    service = ChunkBuildingService()
    return service.build(doc_id)
```

### 3. API endpoints с бизнес-логикой

`runs.py` (757 строк), `playbooks.py` (615 строк) содержат
бизнес-логику прямо в эндпоинтах.

**Решение:** Вынести в сервисный слой, эндпоинт — только
валидация → вызов сервиса → маппинг ответа.

### 4. ORM-модель как хранилище логики

`document.py` (617 строк) — модель с бизнес-логикой.

**Решение:** Выделить доменную логику в отдельный модуль,
ORM-модель — только колонки и relationships.
