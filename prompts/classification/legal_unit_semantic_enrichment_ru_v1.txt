Ты выполняешь semantic enrichment юридической клаузы.

Верни ТОЛЬКО JSON-объект без markdown, без пояснительного текста до JSON и после JSON.

Формат ответа:
{{
  "suggested_unit_type": "one_of_allowed_values_or_null",
  "suggested_clause_function": "one_of_allowed_values_or_null",
  "suggested_topics": ["topic_1", "topic_2"],
  "confidence": 0.0,
  "reasoning": "short explanation",
  "evidence_quotes": ["exact quote from clause text", "another quote"]
}}

ОГРАНИЧЕНИЯ:
- Ты НЕ меняешь иерархию документа, parent-child связи или IDs.
- Ты только предлагаешь semantic metadata для одного уже существующего legal unit.
- Если не уверен — используй null или пустой список. Будь консервативен.
- suggested_topics ДОЛЖНЫ быть только из списка allowed_topics.
- evidence_quotes ДОЛЖНЫ быть точными короткими цитатами из текста текущей клаузы.
- Дай 1-3 цитаты, которые реально подтверждают твою классификацию.
- НЕ выдумывай текст, которого нет в clause.
- Текст клаузы обычно на русском языке, но может быть на английском или двуязычным.
- Классифицируй по юридическому смыслу, независимо от языка текста.
- Значения suggested_unit_type, suggested_clause_function и suggested_topics возвращай строго в английском canonical формате.
- confidence должен быть числом от 0 до 1.

КРИТИЧЕСКОЕ УТОЧНЕНИЕ ПО suggested_clause_function:
- Выбирай clause_function по ПЕРВИЧНОЙ функции клаузы, а не по отдельным словам.
- Не выбирай obligations только потому, что в тексте есть "shall", "must", "обязан", "должен".
- Если основная функция — ограничить/исключить ответственность или убытки, выбирай limitations.
- Если основная функция — описать последствия нарушения, indemnity, damages, compensation, cure, penalty, выбирай remedies.
- Если основная функция — описать порядок действий, механизм, сроки, notice workflow, termination mechanics, выбирай procedures.
- Если основная функция — заверения, гарантии, representations/warranties, выбирай representations.
- Если основная функция — определение термина, выбирай definitions.
- Если это institutional / miscellaneous contract clause (governing law, jurisdiction, notices, waiver, severability, amendment, entire agreement) и более специфичная функция не доминирует, выбирай boilerplate.

ИНСТРУКЦИЯ:
1. Определи наиболее вероятный legal semantic type по тексту и контексту.
2. Определи PRIMARY functional role этой клаузы.
3. Для clause_function выбирай по основной юридической функции, а не по отдельным словам.
4. Выбери только релевантные topic tags из разрешённой taxonomy.
5. Если deterministic baseline выглядит разумно, можешь его подтвердить.
6. Если baseline выглядит неполным, предложи более точное semantic enrichment.
7. Приведи 1-3 короткие точные цитаты из текста clause как evidence.
8. reasoning должен быть коротким, конкретным и опираться на текст клаузы.

ПРАВИЛА ПРИОРИТЕТА ДЛЯ CLAUSE FUNCTION:
- term definition / "means" / "означает" -> definitions
- representations / warranties / guarantees / заверяет / гарантирует -> representations
- limitation / exclusion / cap on liability / consequential damages / ограничение ответственности -> limitations
- indemnity / damages / compensation / penalty / cure / возмещение убытков / неустойка -> remedies
- process / procedure / steps / timeline / termination mechanics / порядок / процедура / сроки -> procedures
- governing law / jurisdiction / notices / waiver / severability / amendment / entire agreement -> boilerplate
- duties / mandatory performance / обязуется / обязан / shall perform -> obligations
- rights / entitlement / may / вправе / имеет право -> rights
