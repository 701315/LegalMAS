Принципы интерпретации:
- Используй ТОЛЬКО информацию из текста договора, который уже включён в semantic prompt.
- Не придумывай факты и значения, которых нет в тексте.
- Если формулировка в договоре неоднозначна, выбери наиболее консервативное толкование.
- Если информации явно недостаточно, допустимо установить value = null
  и снизить confidence, но не выдумывать значение.

Контракт location:
- Для каждого поля по возможности указывай `"location"`.
- `"location"` должен быть либо объектом:
  `{"clause_ref": "п. 12.1", "page": 7, "quote": "дословная фраза из договора"}`
  либо `null`.
- `clause_ref` — короткая ссылка на пункт / раздел / статью именно в том виде,
  как она написана в тексте договора.
- `page` — целое число страницы.
- `quote` — дословная фраза из текста договора (НЕ пересказ, НЕ парафраз),
  которая является источником значения поля. Копируй её посимвольно,
  сохраняя формулировку и порядок слов. Оптимальная длина: 30–300 символов.
  Если значение поля выведено из конкретной фразы договора, quote ДОЛЖЕН
  содержать эту фразу без изменений.
- Если ты не уверен в точной ссылке или не можешь выделить дословную фразу,
  укажи `"location": null`.
- Не выдумывай location или quote по догадке.

Правила заполнения полей:
- Для строковых полей копируй формулировку из договора максимально близко
  к исходному тексту (по смыслу и ключевым словам).
- Если указаны допустимые значения (enum), выбери СТРОГО одно значение
  из этого списка как строку.
- Если значение указано в договоре в другой форме (например, "десять рабочих дней"),
  можешь привести к более стандартному виду, не меняя смысла.
- Если по полю нет достаточной информации, установи `"value": null`
  и задай `"confidence"` низким (например, 0.2–0.3).
- Если информация есть, но она косвенная или не полностью однозначная,
  заполни `"value"` по наилучшему выводу и поставь средний уровень `"confidence"`
  (например, 0.5–0.7).
- Высокий confidence (0.8–1.0) используй только при прямом и однозначном указании
  в тексте.
- Если точную ссылку для поля указать нельзя, оставь `"location": null`.

ЖЁСТКИЕ правила формата ответа:
- Выведи ТОЛЬКО один валидный JSON-объект с корневым ключом "fields".
- Не добавляй никакого текста до или после JSON (никаких пояснений,
  комментариев, Markdown, бэктиков ``` и т.п.).
- Все ключи и строковые значения должны быть в двойных кавычках.
- Для полей с перечислимым набором значений выбирай СТРОГО одно значение
  из списка.
- Не добавляй поля, которых нет в описанной схеме.
- Для каждого поля возвращай объект с ключами:
  - `"value"`
  - `"confidence"`
  - `"location"`
- Если `"location"` не `null`, объект `"location"` содержит ключи:
  - `"clause_ref"` (опционально, если пункт известен)
  - `"page"` (опционально, если страница известна)
  - `"quote"` (обязательно, дословная фраза из текста договора,
    послужившая источником значения поля)
- Начни ответ сразу с символа {.
